# v0.5 Verification Runbook

This runbook verifies the local operational-observability scope: bounded request
correlation, allowlisted JSON application logs, Prometheus scraping and the
provisioned Grafana dashboard. It builds on the API and local PostgreSQL setup
from the [v0.2 runbook](v0.2-verification.md).

## Prerequisites

- Docker Desktop or a compatible Docker daemon;
- Python 3.13 and `uv`;
- Node.js 24 and pnpm 11.23 when running the frontend release checks.

## Start the API and Monitoring Stack

From the repository root, prepare PostgreSQL and start the API in one terminal:

```bash
uv sync --all-groups --locked
docker compose up -d postgres
uv run alembic upgrade head
uv run uvicorn document_platform.bootstrap:app --reload --no-access-log
```

In another terminal, start the optional monitoring profile:

```bash
docker compose --profile observability up -d prometheus grafana
```

Wait until both containers are healthy:

```bash
docker compose --profile observability ps prometheus grafana
```

Prometheus is available at `http://localhost:9090`; Grafana is available at
`http://localhost:3000` with the local-only credentials `admin` /
`local-development-only`.

## Verify Request Correlation and Logs

Call the liveness endpoint with a safe caller-provided correlation ID:

```bash
curl --include http://localhost:8000/health/live \
  --header 'X-Correlation-ID: v050-demo-request-001'
```

The response must contain the same `X-Correlation-ID` value. The API terminal
must contain one JSON event with all of the following fields:

```text
event = http_request_completed
correlation_id = v050-demo-request-001
http_method = GET
http_route = /health/live
http_status = 200
duration_seconds = <number>
```

Repeat the request without the header. The API must return a generated UUID in
`X-Correlation-ID`. Do not use a document ID, filename, token or request URL as
a correlation value.

## Verify Prometheus

Generate a few API observations, then wait up to one scrape interval (15
seconds):

```bash
curl --fail http://localhost:8000/health/live
curl --fail http://localhost:8000/metrics > /dev/null
```

Confirm that Prometheus is scraping the API:

```bash
curl --fail --silent \
  'http://localhost:9090/api/v1/query?query=up%7Bjob%3D%22document-platform-api%22%7D'
```

The result must contain value `"1"`. In the Prometheus expression browser,
inspect these queries:

```text
document_platform_processing_runs
document_platform_processing_queue_oldest_age_seconds
sum by (route, status_class) (rate(document_platform_http_requests_total[5m]))
histogram_quantile(0.95, sum by (le, route) (rate(document_platform_http_request_duration_seconds_bucket[5m])))
```

The run-state metric exposes only the bounded status enum. Request metrics use
method, route template and status class; no document-derived value is a label.

## Verify Grafana Provisioning

Use the Grafana API to confirm the datasource and dashboard, without manually
creating either resource:

```bash
curl --fail --silent --user admin:local-development-only \
  http://localhost:3000/api/datasources/uid/prometheus/health
curl --fail --silent --user admin:local-development-only \
  http://localhost:3000/api/dashboards/uid/document-platform-operations
```

The datasource health response must be `OK`; the dashboard response must report
`provisioned: true`. In the browser, **Document Platform Operations** must show
five panels: API scrape, oldest queued run, processing runs by current status,
HTTP request rate and HTTP latency p95.

## Run Release Quality Gates

From the repository root:

```bash
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

Run the frontend checks from `apps/operator-console`:

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build-storybook
pnpm test:a11y:browser
```

## Current Limits

- The profile is local development infrastructure, with local-only credentials
  and seven-day Prometheus retention; it is not production deployment.
- Grafana provisioning is authoritative and read-only in the UI; dashboard
  changes must be made in the versioned files.
- Correlation is scoped to one HTTP request. Temporal propagation and distributed
  tracing are separate work.
- Current run counts are snapshots, not historical throughput or audit events.
- Alert rules, notification delivery and production access policy remain out of
  scope.

Stop the local monitoring containers when finished:

```bash
docker compose --profile observability stop grafana prometheus
```
