# v0.6 Verification Runbook

This runbook verifies controlled reprocessing from a completed document through
the durable Temporal handoff. It proves that a request creates a new immutable
run, preserves lineage and does not overwrite the source run. It builds on the
local processing setup described in the [v0.2 runbook](v0.2-verification.md)
and the local review authentication fixture described in the
[v0.3 runbook](v0.3-verification.md).

## Prerequisites

- Docker Desktop or a compatible Docker daemon;
- Python 3.13 and `uv`;
- `curl` and `jq`;
- a review token with at least 32 characters;
- a completed, auto-approved invoice from the v0.2 flow.

Use a unique document for this verification. Reprocessing intentionally creates
new durable records, so this is not a read-only check.

## Start the Local Stack

From the repository root, start PostgreSQL and Temporal, apply migrations, then
configure the local review fixture before starting the API:

```bash
uv sync --all-groups --locked
docker compose --profile temporal up -d
uv run alembic upgrade head
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN='local-review-operator-token-for-demo-only-2026'
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_ID='demo-reviewer'
uv run uvicorn document_platform.bootstrap:app --reload --no-access-log
```

In two additional terminals, start the dispatcher and worker:

```bash
uv run python -m document_platform.dispatcher
```

```bash
uv run python -m document_platform.worker
```

The API is available at `http://localhost:8000`; the Temporal UI is available
at `http://localhost:8233`. The optional operator console can be started as
described in the root README.

## Prepare a Terminal Source Run

Upload a valid invoice using the v0.2 flow, then poll its status until it is
automatically approved. Record its document ID as `DOCUMENT_ID`:

```bash
export DOCUMENT_ID='<completed-document-id>'
curl --fail --silent http://localhost:8000/api/v1/documents/$DOCUMENT_ID | jq '{document_status: .status, run_status: .current_run.status, run_id: .current_run.id}'
```

The source must report:

```text
document_status = APPROVED
run_status = COMPLETED
```

`REVIEW_REQUIRED` is deliberately not eligible for reprocessing. Resolve that
review through the v0.3 flow first, then use the resulting completed run.

## Request and Replay Reprocessing

Use a new bounded idempotency key and a concise operator reason. Save the
response because it is the authoritative link between source and replacement
runs:

```bash
export REPROCESSING_KEY='v060-reprocess-001'
curl --fail-with-body --silent --request POST \
  http://localhost:8000/api/v1/documents/$DOCUMENT_ID/reprocessing-requests \
  --header "Authorization: Bearer $DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN" \
  --header "Idempotency-Key: $REPROCESSING_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"reason":"Verified corrected local processing configuration."}' \
  | tee /tmp/document-platform-reprocessing.json | jq .
```

The response status is `202` and contains `replayed: false`. Capture the IDs:

```bash
export SOURCE_RUN_ID=$(jq -r '.source_run_id' /tmp/document-platform-reprocessing.json)
export REPLACEMENT_RUN_ID=$(jq -r '.replacement_run_id' /tmp/document-platform-reprocessing.json)
```

Repeat the exact request with the same idempotency key and payload. It must
return the original operation with `replayed: true`; it must not create another
replacement run:

```bash
curl --fail-with-body --silent --request POST \
  http://localhost:8000/api/v1/documents/$DOCUMENT_ID/reprocessing-requests \
  --header "Authorization: Bearer $DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN" \
  --header "Idempotency-Key: $REPROCESSING_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"reason":"Verified corrected local processing configuration."}' \
  | jq .
```

## Verify the Active-Run Guard

The worker can complete a small synthetic invoice quickly, so verify the active
run guard deterministically. Stop the worker with `Ctrl-C` in its terminal
while leaving the API and dispatcher running. Submit a new reprocessing request
with a fresh key, then confirm the replacement run is `QUEUED`:

```bash
curl --fail --silent http://localhost:8000/api/v1/documents/$DOCUMENT_ID | jq '{document_status: .status, run_status: .current_run.status, run_id: .current_run.id}'
```

While that run is active, a second request using a different idempotency key
must receive `409` with `urn:problem:reprocessing-conflict`. A request using the
original key but a different reason must receive `409` with
`urn:problem:reprocessing-idempotency-conflict`.

Restart the worker before continuing the completion check:

```bash
uv run python -m document_platform.worker
```

## Verify Workflow Completion and Lineage

Poll the document until the replacement workflow finishes:

```bash
curl --fail --silent http://localhost:8000/api/v1/documents/$DOCUMENT_ID | jq '{document_status: .status, run_status: .current_run.status, run_id: .current_run.id, previous_run_id: .current_run.previous_run_id}'
```

For the valid invoice used above, the final projection must report:

```text
document_status = APPROVED
run_status = COMPLETED
run_id = REPLACEMENT_RUN_ID
previous_run_id = SOURCE_RUN_ID
```

The original run remains terminal and is never restarted. In Temporal UI, the
replacement workflow has its own execution history; it is not a retry of the
source workflow.

Inspect the durable audit record without exposing document text or blob paths:

```bash
docker compose exec -T postgres psql -U document_platform -d document_platform \
  --command "SELECT document_id, source_run_id, replacement_run_id, requested_by, reason, requested_at FROM reprocessing_operations WHERE document_id = '$DOCUMENT_ID' ORDER BY requested_at DESC;"
```

The latest row must contain the captured source and replacement IDs, the
configured `demo-reviewer` identity and the supplied reason.

## Verify the Console

Open the completed document in the operator console. Its processing status
shows the predecessor run ID. The reprocessing panel accepts the local token
and a reason, then replaces the form with the persisted request outcome. The
console must keep showing that outcome while the replacement run is queued or
running, and it must not display extracted text, storage paths or the token.

## Current Limits

- Reprocessing reuses the immutable local blob; it does not implement document
  replacement, retention or malware scanning.
- The bearer token is a local development fixture, not production identity or
  authorization.
- The runbook exercises the durable workflow handoff but does not claim a
  production deployment, multi-tenant access policy or notification channel.

Stop local services when finished:

```bash
docker compose --profile temporal down
```
