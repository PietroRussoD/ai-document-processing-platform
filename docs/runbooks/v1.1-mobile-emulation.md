# v1.1 Mobile Browser Emulation

Executed on 2026-10-17 against the local Compose demo using the existing
Playwright `mobile` project in `apps/operator-console/playwright.demo.config.ts`.
The context used Chromium with `isMobile` and `hasTouch` enabled. Two temporary
read-only scenarios passed: one digital invoice and one scanned invoice.

## Checked

- Both documents opened in the review workspace at 390 × 844 CSS px.
- The browser exposed touch points and a coarse pointer. The scenarios used
  touch `tap` actions to switch between Invoice fields and Source PDF and to
  open the embedded PDF preview.
- The PDF iframe loaded with a non-empty source and non-zero dimensions; the
  Open PDF in new tab link was available. The tests did not open that link.
- A temporary review note remained after switching from the PDF panel back to
  Invoice fields.
- The page had no horizontal overflow at 390 × 844 or after resizing the
  viewport to 844 × 390 CSS px.
- No approval or rejection was submitted.

Result: **2 passed**. The temporary test file was removed after the run; this
record summarizes its assertions and result.

## Limits

This was browser emulation on a Mac, not a physical phone. It does not verify
physical-device browser differences, native PDF zoom/pan gestures, opening the
separate PDF tab, the on-screen keyboard, screen-reader speech, safe areas, or
sensor-driven orientation changes. The landscape check resized the emulated
viewport; it did not rotate hardware.

A separate desktop-browser resize to 320 px showed a 15 px horizontal
scrollbar while the document body has a 320 px minimum width. That desktop
scrollbar result is not a physical-mobile result; behavior at 320 px in a
touch-enabled mobile context remains unchecked.

Physical-device checks remain pending. See the
[manual release checklist](v1.1-manual-release-checklist.md).
