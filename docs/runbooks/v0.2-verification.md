# v0.2 Verification Runbook

This runbook verifies the local asynchronous processing scope introduced after
`v0.1`: durable Temporal handoff, bounded extraction, deterministic invoice
validation and safe operator visibility.

## Prerequisites

- Docker Desktop or a compatible Docker daemon;
- Python 3.13 and `uv`;
- Node.js 24 and pnpm 11.23;
- Tesseract with the configured language data for OCR-recommended documents.

## Start the Local Stack

From the repository root:

```bash
uv sync --all-groups --locked
docker compose --profile temporal up -d
uv run alembic upgrade head
```

Wait for PostgreSQL to become healthy:

```bash
docker compose ps postgres
```

Start each process in its own terminal:

```bash
uv run uvicorn document_platform.bootstrap:app --reload
```

```bash
uv run python -m document_platform.dispatcher
```

```bash
uv run python -m document_platform.worker
```

The API is available at `http://localhost:8000`; Temporal UI is available at
`http://localhost:8233`. Start the console separately when verifying the UI:

```bash
cd apps/operator-console
pnpm install --frozen-lockfile
pnpm dev
```

## Verify an Approved Invoice

Upload a valid PDF containing explicitly labelled fields in the supported
format. The deterministic parser recognizes labels such as:

```text
Invoice number: INV-42
Invoice date: 2026-09-17
Supplier: Acme Ltd
Total: EUR 39.98
```

Use a unique idempotency key for each new document:

```bash
curl --fail-with-body --request POST http://localhost:8000/api/v1/documents \
  --header 'Idempotency-Key: invoice-approved-001' \
  --form 'document=@<path-to-invoice.pdf>;type=application/pdf'
```

Poll the returned document ID until the response reports:

```text
document.status = APPROVED
current_run.status = COMPLETED
current_run.processing_output.invoice_validation.decision = AUTO_APPROVE
```

The projection can contain field values, counts, decisions and reason codes. It
must not contain extracted document text, a blob path or a storage key.

## Verify a Review Handoff

Upload an otherwise valid invoice that deliberately omits one required field,
such as `Invoice date`. The eventual projection must report:

```text
document.status = REVIEW_REQUIRED
current_run.status = REVIEW_REQUIRED
current_run.processing_output.invoice_validation.decision = REVIEW_REQUIRED
current_run.processing_output.invoice_validation.issues contains MISSING_ISSUE_DATE
```

The console stops polling after this state and presents the review reasons. It
does not yet provide an action to resolve the review.

## Verify the Console

At `http://localhost:5173`, submit each PDF and confirm that the persisted
timeline shows text extraction, OCR fallback, canonical-text selection,
classification, invoice extraction, invoice validation and either completion or
review handoff. The console must not render the PDF source text.

## Verify Quality Gates

Run backend checks from the repository root:

```bash
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

Run frontend checks:

```bash
cd apps/operator-console
pnpm check
```

## Current Limits

- Invoice parsing and validation are deterministic, deliberately conservative
  and limited to supported labels and formats.
- `REVIEW_REQUIRED` is a durable handoff state; resolving it is not implemented.
- Authentication, notifications, retention and S3-compatible storage are not
  implemented.
- The local Temporal and PostgreSQL credentials are development-only.

Stop local services when finished:

```bash
docker compose --profile temporal down
```
