# v0.9 Local Demo Walkthrough

This is a five-minute walkthrough **after the local processing stack is ready**.
Use synthetic data only. The Compose setup has development credentials and is
not a deployment for untrusted or confidential documents.

## Prepare the Stack

From the repository root:

```bash
docker compose --profile processing up --build -d
docker compose --profile processing ps
uv sync --all-groups
uv run python scripts/verify_processing_compose.py
```

The script uploads one generated PDF through the console proxy, waits for
persisted embedded-text extraction and invoice classification, and requires the
document and run to reach `REVIEW_REQUIRED`. It prints a `Console document:` URL.
Open that exact URL. If the console uses another host port, run the script with
`--base-url http://127.0.0.1:<port>`.

Each execution creates a new document ID and idempotency key. The PDF content
and expected outcome are fixed; IDs and timestamps are not. Repeated runs leave
synthetic records in the local database.

## Five-Minute Route

1. Open the printed console URL. The selected document detail should show
   `REVIEW_REQUIRED`, with its current processing run in the same state.
2. Inspect the persisted processing output: embedded-text extraction,
   `INVOICE` classification and the validation result. The console displays
   metadata and structured fields, not the original PDF text or blob path.
3. Open **Needs review** in the work queues. The synthetic document should be
   present there; switching queues clears the selected detail, so reopen it
   from the row if needed. Do not approve it without valid corrections.
4. Open **System Map**. Select the API, dispatcher, Temporal and worker to see
   their responsibilities, then choose the **Review-required invoice** journey.
   This is a static reference path, not a live trace of the uploaded document.
5. Follow the OpenAPI, ADR and security-limitation links under **Technical
   references**. They point to versioned repository evidence.

The script is a local smoke test, not a CI or browser test. A separate browser
check is required before declaring the `v0.9.0` demo verified.

Stop the stack with `docker compose down` when finished. Do not use `-v` unless
you deliberately want to discard the local database and document volumes.
