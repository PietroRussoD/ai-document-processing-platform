# v0.7 Verification Runbook

This runbook verifies the terminal workflow-failure path and its controlled
recovery. It injects one local extraction failure, proves that PostgreSQL stores
safe evidence after Temporal exhausts the activity retry policy, then creates a
replacement run with immutable lineage.

## Prerequisites

- Docker Desktop or a compatible Docker daemon;
- Python 3.13 and `uv`;
- `curl` and `jq`;
- a local-only review token with at least 32 characters.

This verification writes a synthetic document, processing runs and a
reprocessing audit record to PostgreSQL. Use a fresh local database or unique
idempotency keys.

## Start the Local Stack

From the repository root, start PostgreSQL and Temporal, apply migrations, and
configure the local review fixture:

```bash
uv sync --all-groups --locked
docker compose --profile temporal up -d
uv run alembic upgrade head
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN='local-failure-verification-token-2026'
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_ID='local-verifier'
```

In separate terminals, start the API and dispatcher:

```bash
uv run uvicorn document_platform.bootstrap:app --reload --no-access-log
```

```bash
uv run python -m document_platform.dispatcher
```

Start a worker with the intentionally local-only extraction fault enabled:

```bash
DOCUMENT_PLATFORM_FAULT_INJECTION_STAGE=EMBEDDED_TEXT_EXTRACTION \
  uv run python -m document_platform.worker
```

## Submit a Synthetic PDF

Create a small local PDF and upload it with a unique key:

```bash
uv run python -c 'import pymupdf; document = pymupdf.open(); page = document.new_page(); page.insert_text((72, 72), "Synthetic failure verification invoice"); document.save("/tmp/document-platform-failure-demo.pdf")'
curl --fail-with-body --silent --request POST http://localhost:8000/api/v1/documents \
  --header 'Idempotency-Key: v070-failure-demo-001' \
  --form 'document=@/tmp/document-platform-failure-demo.pdf;type=application/pdf' \
  | tee /tmp/document-platform-failure-upload.json | jq .
export DOCUMENT_ID=$(jq -r '.document_id' /tmp/document-platform-failure-upload.json)
```

Wait for the three bounded extraction attempts to finish, then inspect the
public status projection:

```bash
curl --fail --silent http://localhost:8000/api/v1/documents/$DOCUMENT_ID \
  | jq '{document_status: .status, run_status: .current_run.status, run_id: .current_run.id, failure: .current_run.failure}'
```

It must report:

```text
document_status = FAILED
run_status = FAILED
failure.stage = EMBEDDED_TEXT_EXTRACTION
failure.code = ACTIVITY_RETRY_EXHAUSTED
```

The public endpoint omits raw exception details. Verify that the same safe
evidence was persisted in the local database:

```bash
docker compose exec -T postgres psql -U document_platform -d document_platform \
  --command "SELECT status, failure_stage, failure_code FROM processing_runs WHERE document_id = '$DOCUMENT_ID' ORDER BY queued_at DESC LIMIT 1;"
```

The row must contain:

```text
FAILED | EMBEDDED_TEXT_EXTRACTION | ACTIVITY_RETRY_EXHAUSTED
```

## Recover with a Replacement Run

Stop the fault-injecting worker and start a normal worker in its place:

```bash
uv run python -m document_platform.worker
```

Request controlled reprocessing with a new idempotency key:

```bash
export REPROCESSING_KEY='v070-failure-recovery-001'
curl --fail-with-body --silent --request POST \
  http://localhost:8000/api/v1/documents/$DOCUMENT_ID/reprocessing-requests \
  --header "Authorization: Bearer $DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN" \
  --header "Idempotency-Key: $REPROCESSING_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"reason":"Verified recovery after local extraction fault injection."}' \
  | tee /tmp/document-platform-failure-recovery.json | jq .
export SOURCE_RUN_ID=$(jq -r '.source_run_id' /tmp/document-platform-failure-recovery.json)
export REPLACEMENT_RUN_ID=$(jq -r '.replacement_run_id' /tmp/document-platform-failure-recovery.json)
```

Poll the status endpoint until the replacement reaches a business terminal
state. The synthetic PDF normally reaches `REVIEW_REQUIRED`, because it lacks
the required invoice fields. A complete synthetic invoice can reach `APPROVED`.
Neither result may be `FAILED` solely because of the previous injected fault.

Verify the immutable lineage and that the source retains its failure evidence:

```bash
docker compose exec -T postgres psql -U document_platform -d document_platform \
  --command "SELECT id, previous_run_id, status, failure_stage, failure_code FROM processing_runs WHERE document_id = '$DOCUMENT_ID' ORDER BY queued_at;"
```

The source run must remain `FAILED` with the two safe failure values. The
replacement must reference `SOURCE_RUN_ID` through `previous_run_id` and have
null failure values after normal execution.
