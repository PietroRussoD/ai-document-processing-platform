# v0.4 Verification Runbook

This runbook verifies immutable operator corrections and the local-model
evaluation boundary. It builds on the local stack and review handoff from the
[v0.3 runbook](v0.3-verification.md).

## Prerequisites

- Docker Desktop or a compatible Docker daemon;
- Python 3.13 and `uv`;
- a review token with at least 32 characters;
- a synthetic PDF containing the labelled invoice fields below, deliberately
  omitting `Invoice date`.

```text
Invoice number: INV-V04-001
Supplier: Acme Supplies Ltd
Total: EUR 149.99
```

## Start the Local Stack

Use the start commands in the [v0.2 runbook](v0.2-verification.md), then set
the local review fixture before starting the API:

```bash
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN='local-review-operator-token-for-demo-only-2026'
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_ID='demo-reviewer'
```

Start the API, dispatcher and worker as separate processes. Upload the synthetic
PDF with a unique idempotency key and poll its status until both the document and
current processing run are `REVIEW_REQUIRED`.

## Verify Correction Validation

First, attempt an approval without corrections. It must return `409` with
`urn:problem:review-invoice-incomplete`; a reviewer must not be able to approve
an invoice whose effective fields are still incomplete.

Then approve it with the missing date:

```bash
curl --fail-with-body --request POST \
  http://localhost:8000/api/v1/documents/<document-id>/review-resolution \
  --header "Authorization: Bearer $DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{
    "decision": "APPROVE",
    "review_note": "Verified the invoice date.",
    "corrections": [
      {"field": "ISSUE_DATE", "corrected_value": "2026-09-19"}
    ]
  }'
```

The first response must report `replayed: false`. A following status response
must report:

```text
document.status = APPROVED
current_run.status = COMPLETED
current_run.review_resolution.decision = APPROVE
current_run.review_resolution.reviewer_id = demo-reviewer
current_run.review_resolution.corrections[0].field = ISSUE_DATE
current_run.review_resolution.corrections[0].corrected_value = 2026-09-19
```

The original `processing_output.invoice_extraction.issue_date` remains `null`.
This proves the correction was recorded as a separate immutable fact rather
than overwriting the extraction.

Repeat the exact approval request. It must return `replayed: true` and retain
the original correction timestamp. A changed correction, decision or review
note must return `409` rather than overwrite the accepted review.

## Verify the Console

At `http://localhost:5173`, a review-required invoice pre-populates the
extracted values. Enter `2026-09-19` for the missing date and approve it with
the configured token. The resolved view shows the effective date and identifies
it as corrected; it does not replace or reveal source-document text.

## Verify Local Model Evaluation

The local comparison is independent from the document-processing stack. With
Ollama running and a local model available, execute:

```bash
uv run python scripts/evaluate_ollama_invoice_extraction.py --model <local-model> --timeout-seconds 60
```

The output contains exact-match results, failed-request count and local API-call
latency. It is evaluation evidence only: it must not alter the workflow,
database records or review path.

## Recorded Local Verification

Local verification completed on 2026-09-19 against the isolated PostgreSQL
instance on host port `5433` and local Temporal profile:

- the synthetic invoice reached `REVIEW_REQUIRED` with
  `MISSING_ISSUE_DATE` after embedded-text extraction, OCR fallback, canonical
  text selection and deterministic invoice validation;
- an approval without a correction returned `409`
  `urn:problem:review-invoice-incomplete`;
- approval with `ISSUE_DATE = 2026-09-19` atomically produced document
  `APPROVED` and run `COMPLETED`;
- the status projection retained `invoice_extraction.issue_date = null` and
  exposed the separate immutable correction record;
- the identical request returned `replayed: true` with the original timestamp;
- a changed correction returned `409`
  `urn:problem:review-resolution-conflict`.

## Current Limits

- Corrections are field-level facts tied to one processing run; they are not a
  general versioned document-editing system.
- The static bearer token remains a local development fixture, not user
  management or enterprise authorization.
- The recorded Qwen3 benchmark is insufficient to replace deterministic
  extraction and remains outside the worker.
