# v1.1 Manual Release Checklist

Prepared on 2026-10-16. Every check below is **pending** until a person records
an observation. This document does not claim a new manual verification or
change the development versions.

## Setup

1. Open the running console at `http://127.0.0.1:8088` on the Mac.
2. Upload fresh copies of `examples/documents/invoice-digital.pdf` and
   `invoice-scanned.pdf`. Both should reach review. Keep a separate upload for
   each approval/rejection test, since those actions finish the review.
3. Enter the configured local operator token in Operator access. Obtain it
   from the existing local demo setup; never include it in the result record.
4. Record the commit, macOS/device version, browser version, assistive technology,
   viewport/zoom and fixture used. Start at ordinary browser zoom.
5. In Safari, enable “Press Tab to highlight each item on a webpage” under
   Settings > Advanced for the keyboard-only checks. See
   [Apple's Safari settings guide](https://support.apple.com/en-ie/guide/safari/ibrw1075/mac).
6. Enable VoiceOver from macOS Accessibility settings and use its navigation
   commands as well as ordinary Tab navigation. Record what is actually spoken;
   a DOM label or automated accessibility result is not a speech observation.
   See [Apple's VoiceOver guide](https://support.apple.com/en-mide/guide/voiceover/vo2682/mac).

Use only the supplied synthetic documents. For missing-data error checks,
clear a required field deliberately; restore values from the digital PDF
before approving. The scanned fixture lacks an issue date, so use it for
inspection or rejection rather than inventing a date to obtain approval.

## Physical Mobile PDF Check

The Mac's `127.0.0.1` address is not the phone's loopback server. Establish a
controlled device connection before testing. Keep the current local trust
boundary; do not change service bindings or introduce a public tunnel as part
of this checklist.

For an authorized USB-connected Android device with adb already installed,
reverse forwarding can keep the host service on loopback:

```bash
adb -s DEVICE_SERIAL reverse tcp:8088 tcp:8088
```

Then open `http://localhost:8088` on that device. Remove this forwarding after
the check with `adb -s DEVICE_SERIAL reverse --remove tcp:8088`.
See the [Android local-server guide](https://developer.android.com/develop/ui/views/layout/webapps/access-local-server).
For a physical iPhone/iPad, record the chosen controlled connection separately;
if none is available, mark the device check Not tested. Safari on the Mac and
mobile emulation do not substitute for the physical-device result.

| --- | --- | --- |

| M2 | Open both PDFs in the embedded preview and a separate tab. | Actual pages load; record any browser download/opening fallback, blank frame or authentication failure separately. |

## Result Record

For each ID record **Pass**, **Fail**, **Not tested** or **Deferred**. A deferred
check requires a reason and an explicit release-scope decision; it is not a pass.

```text
Commit / date / tester
Device and OS
Browser and version
Assistive technology and settings
Fixture / viewport / zoom
Check ID / status
Observed behavior (including spoken output when relevant)
Expected behavior / reproduction steps if failed
Evidence location (synthetic data only; no tokens)
Follow-up or deferral reason / decision owner
```

Recommended fix-before-release issues include keyboard/focus traps, unusable
approval or rejection, lost/incorrect corrections, and inability to inspect
source documents through any intended route. Cosmetic or native-viewer
limitations still need a recorded assessment. This is a proposed decision
guide, not an automatic new release gate or WCAG certification.
