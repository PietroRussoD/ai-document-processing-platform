## Local AI-Assisted Review

The digital invoice fixture uses CAD, which the deterministic extractor does
not support. It should reach `REVIEW_REQUIRED`; the optional Ollama stage can
propose the missing currency and amount, but never approves the document.

1. Start Ollama on the host and confirm the configured model is already
   available with `ollama list`. The Compose stack does not download models.
2. Enable the optional provider for the worker and start the local stack:

   ```bash
   DOCUMENT_PLATFORM_OLLAMA_ENABLED=true docker compose --profile processing up --build -d
   ```

   By default, the worker connects to host Ollama at
   `http://host.docker.internal:11434`. Set `OLLAMA_COMPOSE_BASE_URL` if the
   host is reached at another address. Review authentication uses a demo-only
   token, overridable in `.env`; ports bind to loopback. Do not expose this
   setup or reuse the token outside the local demo.
3. Open `http://localhost:8088` and upload
   `examples/documents/invoice-digital.pdf`. Wait for `REVIEW_REQUIRED` and
   inspect the proposal beside the deterministic result. Enter the configured
   review token and use **View source PDF** to inspect the original when needed;
   the PDF is fetched only after that action.
4. Use the per-field proposal actions to copy values into the correction form,
   then approve. Approval records corrections with `AI_PROPOSAL` provenance;
   it does not rewrite the original deterministic extraction. Always compare
   values with the original document before resolving review. The scanned
   fixture intentionally has no issue date, so do not invent one: leave it
   pending or reject it with a note explaining why.

On 2026-09-28, this flow was verified locally with `qwen3:8b`: it proposed
`CAD` and `99.0000`; the operator copied and approved both fields. The API
returned `APPROVED`, preserved the deterministic null values, and recorded
both correction sources as `AI_PROPOSAL`. This is an observed local run, not a
guarantee of model output. Model proposals are advisory and must be checked by
the operator.

The one-shot browser test passed on the desktop project; its before/after

For a new local run, upload a fresh synthetic digital invoice, wait for AI
execution to finish, and set `DEMO_DOCUMENT_URL` to its Console URL and
`DEMO_REVIEW_TOKEN` to the local review token. Then run from
`apps/operator-console`:

```bash
./node_modules/.bin/playwright test --config=playwright.demo.config.ts --project=desktop --grep='digital invoice AI proposal'
```

This local-only test mutates the document by approving it. It requires a fresh
review-required run with the expected `CAD`/`99.0000` proposal, cannot be rerun
against an approved document and is not part of ordinary CI. Its ignored trace
may contain the demo token; do not publish trace artifacts.
