# v0.3 Verification Runbook

This runbook verifies the authenticated, immutable resolution of a durable
`REVIEW_REQUIRED` invoice handoff. It builds on the local stack and processing
flow verified by the [v0.2 runbook](v0.2-verification.md).

## Prerequisites

- Docker Desktop or a compatible Docker daemon;
- Python 3.13 and `uv`;
- Node.js 24 and pnpm 11.23 when verifying the operator console;
- a review token with at least 32 characters.

## Start the Local Stack

From the repository root, prepare the local stack as in the v0.2 runbook, then
configure the local review fixture before starting the API:

```bash
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN='local-review-operator-token-for-demo-only-2026'
export DOCUMENT_PLATFORM_REVIEW_OPERATOR_ID='demo-reviewer'
uv run uvicorn document_platform.bootstrap:app --reload
```

Start the dispatcher and worker in separate terminals:

```bash
uv run python -m document_platform.dispatcher
```

```bash
uv run python -m document_platform.worker
```

## Verify a Review Resolution

Upload an otherwise valid invoice that deliberately omits `Invoice date`, as
described in the v0.2 review-handoff check. Poll the returned document ID until
both the document and current processing run are `REVIEW_REQUIRED`.

Resolve the review with either `APPROVE` or `REJECT`:

```bash
curl --fail-with-body --request POST \
  http://localhost:8000/api/v1/documents/<document-id>/review-resolution \
  --header "Authorization: Bearer $DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{"decision":"APPROVE","review_note":"Verified locally."}'
```

The response reports `replayed: false` on the first successful request. A
subsequent status response must report:

```text
document.status = APPROVED
current_run.status = COMPLETED
current_run.review_resolution.decision = APPROVE
current_run.review_resolution.reviewer_id = demo-reviewer
```

With `REJECT`, the document status must be `REJECTED`; the technical run still
becomes `COMPLETED` because processing has ended with a durable business
outcome.

Repeat the same request with the same decision, reviewer and note. It must
return the original resolution with `replayed: true`. A conflicting second
decision or changed note must not overwrite the immutable resolution.

## Verify Authentication

Submit the same endpoint with a wrong bearer token. It must return `401` with
the problem type `urn:problem:review-authentication-rejected`. Starting the API
without `DOCUMENT_PLATFORM_REVIEW_OPERATOR_TOKEN` must make the review action
unavailable rather than accepting an unauthenticated request.

## Verify the Console

Run the operator console as described in the root README. For a review-required
document, the console shows a token field, optional note and explicit approve
and reject controls. A successful decision replaces the form with its persisted
outcome. On a rejected API request, focus moves to the error alert and the
token field references it.

## Current Limits

- The bearer token identifies one configured local reviewer; it is not a user
  directory, session mechanism or enterprise authorization integration.
- The console does not persist the entered token.
- Notifications, retention policy and escalation workflows remain out of scope.
