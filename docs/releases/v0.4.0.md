# v0.4.0 - Auditable Invoice Corrections

## Scope

`v0.4.0` completes the first review-correction path for invoices. An operator
can approve a review-required invoice after supplying a missing or corrected
field, while the original deterministic extraction remains immutable evidence.

This release also establishes a synthetic baseline for evaluating local
structured extraction. It records a Qwen3 comparison as evidence, rather than
turning an unproven model into a production workflow dependency.

## Included

- typed, non-empty invoice correction sets persisted separately from extraction
  and associated with one immutable review resolution;
- validation of the effective invoice before an approval is accepted;
- atomic persistence of a resolution and its correction records;
- idempotent replay for an identical correction request and conflict rejection
  for a changed decision, note or correction set;
- status and generated OpenAPI types exposing original extraction facts and
  separate corrections;
- accessible console inputs that pre-populate extracted invoice fields and mark
  effective values supplied by a reviewer;
- a versioned synthetic invoice-extraction corpus and deterministic evaluator;
- an evaluation-only Ollama client using structured JSON, temperature zero and
  disabled thinking;
- recorded local Qwen3 benchmark evidence and a repeatable correction and
  evaluation verification runbook.

## Verification

Follow the [v0.4 verification runbook](../runbooks/v0.4-verification.md) from
a clean checkout after the `v0.2` local-stack prerequisites are available.

Local verification completed on 2026-09-19:

- an invoice missing its issue date reached `REVIEW_REQUIRED` after bounded
  extraction, OCR fallback and deterministic validation;
- approval without a correction returned `409`
  `urn:problem:review-invoice-incomplete`;
- approval with a corrected issue date atomically produced document `APPROVED`
  and processing run `COMPLETED`;
- status retained the original null issue date and exposed a separate immutable
  correction record;
- identical resolution replay returned `replayed: true`, while a changed
  correction returned `409 urn:problem:review-resolution-conflict`;
- the synthetic deterministic evaluator and Qwen3 benchmark completed with
  repeatable artifacts; Qwen3 reached four exact matches out of eight and was
  deliberately kept outside the application workflow;
- Ruff, formatting, Pyright and 296 backend tests passed at 86.80% coverage.
- frontend contract generation, formatting, linting, TypeScript, 48 tests at
  93.88% statement coverage, the production build and Storybook build passed;
- five local Chromium/axe accessibility checks passed.

The final release gate is the equivalent CI run on the commit selected for the
`v0.4.0` tag.

## Deliberately Excluded

- model-driven extraction in the Temporal workflow or persisted business state;
- a general document-editing or multi-version correction system;
- enterprise identity, user management and fine-grained authorization;
- notifications, escalation and retention workflows;
- S3-compatible storage and production deployment.

The static bearer token remains a local development fixture. The local-model
benchmark is decision evidence, not a production-readiness claim.

## Compatibility

The `/api/v1` namespace remains stable. Existing status consumers that ignore
unknown fields remain compatible. Consumers that need an effective reviewed
invoice must intentionally combine the immutable extraction and correction
facts; no API response silently rewrites the source extraction.
