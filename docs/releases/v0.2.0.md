# v0.2.0 - Deterministic Document Processing

## Scope

`v0.2.0` adds the first durable processing workflow to the local-first PDF
ingestion boundary established in `v0.1.0`. It processes accepted business PDFs
asynchronously and exposes only safe, persisted processing metadata to the
operator console.

## Included

- durable PostgreSQL-to-Temporal handoff through claimed workflow requests;
- worker-driven `UPLOADED -> PROCESSING` and `QUEUED -> RUNNING` transitions;
- bounded PyMuPDF embedded-text extraction and conditional local Tesseract OCR;
- immutable canonical-text selection and deterministic document classification;
- deterministic extraction of explicitly labelled invoice fields;
- immutable invoice validation with automatic approval or review handoff;
- transactional `APPROVED`/`COMPLETED` and `REVIEW_REQUIRED` lifecycle updates;
- safe status projection, OpenAPI contract and React timeline for all workflow
  stages;
- immutable persistence support for future manual review resolutions;
- backend and frontend quality gates, generated contract types and CI checks.

## Verification

Follow the [v0.2 verification runbook](../runbooks/v0.2-verification.md) from a
clean checkout. It covers local workflow startup, approved invoices, review
handoff, safe status output and both quality suites.

Local verification completed on 2026-09-17:

- an invoice missing an issue date reached `REVIEW_REQUIRED` for both document
  and run, with a persisted validation reason;
- an invoice with all required labelled fields reached document `APPROVED` and
  run `COMPLETED`;
- the API exposed structured metadata and validation reason codes without
  document text, blob paths or storage keys;
- Ruff, formatting, Pyright and 238 backend tests passed at 86.89% coverage;
- frontend contract generation, formatting, linting, TypeScript, 27 tests at
  93.83% statement coverage and the production build passed.

The final release gate is the equivalent CI run on the commit selected for the
`v0.2.0` tag.

## Deliberately Excluded

- authenticated operator identities and permissions;
- HTTP or console actions that approve or reject a manual review;
- Ollama or external-provider extraction;
- S3-compatible storage, notifications, retention and production deployment.

`REVIEW_REQUIRED` is therefore a durable, visible handoff state. The next
milestone resolves it through an authenticated operator action.

## Compatibility

This release preserves the `/api/v1` HTTP namespace. The status response adds
optional `processing_output` metadata; consumers that ignore unknown JSON fields
remain compatible.
