## Release Scope

This release strengthens the local-only boundary. A CI check requires every
published Compose port to bind to `127.0.0.1`. Document API routes require the
shared local operator token; the browser holds it in memory for the current
page session and clears it when access is closed. Health, metrics, OpenAPI and
the Temporal UI remain unauthenticated inside the loopback boundary. The
shared token is not per-user authorization or tenant isolation.

The release remains a source and documentation release for a local portfolio
demo using synthetic, non-sensitive PDFs. Do not host the backend publicly,
use confidential or untrusted documents, or distribute the API runtime image.
The existing CVE findings remain open. Parser isolation is deferred; see the
[PDF parser isolation design](../security/pdf-parser-isolation-design.md).

## Verification

### Local Checks - 2026-10-18

- Backend: Ruff lint and formatting passed, Pyright reported no errors,
  warnings or information, and all 619 tests passed with 89.85% coverage
  (five existing PyMuPDF SWIG deprecation warnings).
- Operator console: generated OpenAPI types matched the contract; Prettier,
  ESLint and TypeScript checks passed; all 166 tests passed with 96.38%
  statement coverage; production build passed. The initial run found a stale
  app-shell test that expected upload before token verification. The test now
  checks the implemented access gate; rerunning the full console check passed.
- Compose configuration: all seven published ports in all profiles bind to
  `127.0.0.1`.
- Runtime smoke test: rebuilt API and console images, started the processing
  profile, uploaded the script's synthetic invoice and observed
  `REVIEW_REQUIRED`. PostgreSQL, Temporal, dispatcher, worker, API and console
  ran through the console proxy. AI inference was not exercised.
- Browser check: the real-stack Playwright document-flow scenario passed at
  desktop and mobile viewports. It entered the operator token, opened the
  review document and navigated to the system map. The other demo scenarios
  require separately prepared document URLs and, for AI recovery scenarios,
  configured failure/recovery cases; those scenarios were not run.
- Images: ARM64 API and console images were scanned with Trivy 0.74.0 and a
  vulnerability database downloaded on 2026-10-18. The API image reported 76
  Debian 13.7 package findings (75 HIGH, 1 CRITICAL; 33 distinct CVEs); no
  HIGH/CRITICAL Python-package findings were reported. The cleanly rebuilt
  console image reported no HIGH/CRITICAL findings. Its first cached build had
  one HIGH finding, `CVE-2026-77214` in `libexpat 2.8.5-r0`; a clean build ran
  the existing `apk upgrade`, installed `2.9.0-r0`, and the rescan found none.
  Image identifiers and scanner limitations are recorded in
  [security and limitations](../security-and-limitations.md).
