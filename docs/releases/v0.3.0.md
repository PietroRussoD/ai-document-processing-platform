# v0.3.0 - Authenticated Review Resolution

## Scope

`v0.3.0` completes the operator path for an invoice that needs human review.
It extends the durable `REVIEW_REQUIRED` handoff introduced in `v0.2.0` with an
authenticated local action that records one immutable business decision and
finishes the technical processing run.

## Included

- static local bearer authentication for the configured review operator;
- `POST /api/v1/documents/{document_id}/review-resolution` with explicit
  `APPROVE` and `REJECT` decisions;
- atomic document and processing-run lifecycle transitions;
- immutable reviewer identity, optional note, decision and resolution time;
- idempotent replay for the same decision, reviewer and note, with conflicting
  corrections rejected;
- safe review-resolution metadata in the existing status projection;
- an accessible React review form with pending feedback, keyboard recovery and
  persisted outcome presentation;
- reusable feedback and button components, Storybook documentation, semantic
  axe checks and local browser accessibility verification;
- a repeatable local review-resolution verification runbook.

## Verification

Follow the [v0.3 verification runbook](../runbooks/v0.3-verification.md) from
a clean checkout after the `v0.2` local-stack prerequisites are available.

Local verification completed on 2026-09-18:

- a synthetic invoice missing its issue date reached `REVIEW_REQUIRED`;
- an authenticated `APPROVE` resolution atomically produced document
  `APPROVED` and run `COMPLETED`;
- repeating the same resolution returned `replayed: true` without a second
  business mutation;
- an incorrect bearer token returned `401` with a problem-details response;
- Ruff, formatting, Pyright and 257 backend tests passed at 87.26% coverage;
- frontend contract generation, formatting, linting, TypeScript, 46 tests at
  95.1% statement coverage, the production build and Storybook build passed;
- five local Chromium/axe accessibility checks passed.

The final release gate is the equivalent CI run on the commit selected for the
`v0.3.0` tag.

## Deliberately Excluded

- enterprise identity, user management and fine-grained authorization;
- notifications, escalation and retention workflows;
- Ollama or external-provider extraction;
- S3-compatible storage and production deployment.

The static bearer token is deliberately a local development fixture. It is not
presented as production authentication.

## Compatibility

This release retains the `/api/v1` namespace. Existing ingestion and status
consumers remain compatible: the status projection only adds optional
review-resolution metadata. The new review-resolution endpoint requires a
configured bearer token and returns problem-details responses for rejected
authentication or invalid state transitions.
