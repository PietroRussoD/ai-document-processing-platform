# v0.1.0 - Reliable PDF Ingestion

## Scope

`v0.1.0` is the first functional milestone of the AI Document Processing
Platform. It establishes a local-first, testable ingestion boundary for
business PDFs before durable processing workflows are introduced.

## Included

- bounded PDF upload with media-type, signature, structural, encryption and
  page-limit validation;
- private content-addressed local blob storage with SHA-256 integrity checks;
- atomic PostgreSQL persistence of documents, queued processing runs and upload
  idempotency results;
- idempotent `POST /api/v1/documents` and persisted
  `GET /api/v1/documents/{document_id}` status projection;
- RFC 9457 responses for expected request failures;
- React operator console for PDF submission and persisted status polling;
- versioned OpenAPI contract with generated TypeScript transport types;
- automated Python and frontend quality gates, coverage thresholds and secret
  scanning in CI.

## Verification

Follow the [v0.1 verification runbook](../runbooks/v0.1-verification.md) from a
clean checkout. The runbook covers local startup, API and console happy paths,
idempotency behavior and both quality suites.

Local verification completed on 2026-09-15:

- API liveness, PDF acceptance, idempotent replay and persisted status
  projection passed against PostgreSQL;
- the Vite development proxy reached the API successfully;
- Ruff, formatting, Pyright and 119 backend tests passed at 94.4% coverage;
- frontend contract, formatting, lint, TypeScript, production build and 18
  frontend tests passed at 96.66% statement and 86.66% branch coverage.

The final release gate is the equivalent CI run on the commit selected for the
`v0.1.0` tag.

## Deliberately Excluded

- Temporal worker execution and restart recovery;
- text extraction, OCR and AI-based structured extraction;
- human review, notifications, authentication and retention workflows;
- S3-compatible storage and production deployment configuration.

An accepted document therefore remains `UPLOADED` and its processing run remains
`QUEUED` in this release. This is the intended boundary, not a processing
failure.

## Compatibility

This is the first public application milestone; no upgrade path from a previous
application release is required. The HTTP API is versioned under `/api/v1`.
