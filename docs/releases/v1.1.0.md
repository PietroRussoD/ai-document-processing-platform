# v1.1.0 - Operator Console Workflows and Usability

Status: in development, unreleased.

Python and API metadata report `1.1.0.dev0`; the operator console reports
`1.1.0-dev.0`. The latest tagged release remains
[v1.0.0](v1.0.0.md).

## Target Scope

This development cycle focuses on the operator console, including document
selection, review validation, draft handling, available recovery actions and
the hierarchy of review information. Changes will be reviewed and verified
incrementally before they are recorded as delivered release features.

## Verification

Release verification is pending. The previous release's checks do not certify
the upcoming console changes. Record the final scope and verification evidence
before replacing the development versions with `1.1.0` and creating a release
tag.

## Implemented Changes

- The Documents page owns one selected document and renders its detail outside
  the upload form and queue rows. Uploading or selecting a document opens the
  same detail; direct links and browser history restore the selection.
- Successful uploads refresh the queues. Queue filtering, pagination and
  refresh keep the selected detail mounted, including when the document leaves
  the visible queue.
- Reprocessing controls require both a terminal processing run and a document
  state accepted by the backend. Unsupported documents explain why reprocessing
  is unavailable. Backend conflicts remain visible without discarding the
  operator's token or reason.
- Review drafts preserve field values, correction sources and notes in memory
  through document selection, closing details and browser history. Tokens are
  excluded. Reloading or leaving the page requests a native browser warning
  whenever unsaved drafts remain, including drafts of hidden documents.
- Successful reviews clear their draft; failed requests preserve it. Invoice
  fields and AI proposal adoption are disabled while a decision is being saved.
- Successful review and reprocessing requests invalidate cached work queues as
  well as the selected document status, so visible queues refresh immediately.
- Differing AI suggestions appear beside their invoice fields with textual
  adoption controls. Fields identify manual and AI-sourced changes, show the
  extracted value and offer restoration or clearing when no value was extracted.
  Restoring removes the correction and its source; manual editing after adoption
  records a manual source. Storybook includes an inline-suggestion example.

- Narrow review workspaces offer separate invoice-field and source-PDF views.
  Both panels stay mounted, preserving drafts, tokens and a loaded PDF across
  view changes. Panels at least 48rem wide continue to show both side by side.
- A valid AI proposal is labeled "Fields parsed" and explains that parseable
  values still need comparison with the PDF and do not approve the invoice.
- Approval guidance distinguishes a persisted operator decision from automatic
  validation. Approved documents without sufficient evidence report that their
  approval origin is unavailable.

### Local Checkpoint - Mobile Review Workspace

All 17 review-form and review-panel tests passed, including unchanged PDF object
URL and request count across view changes, note and credential retention, and
keyboard order. TypeScript, ESLint and the production build passed. Synthetic
browser checks at 320, 390, 1024 and 1440 px confirmed responsive visibility,
no horizontal overflow and draft retention. Mobile keyboard checks skip hidden
panel controls. Axe reported no WCAG A/AA violations in either mobile view after
button transitions completed; the native PDF frame was excluded. Native PDF
contents and the real backend were not verified.

### Local Checkpoint - Inline AI Suggestions

All 40 tests in the review-form, review-panel, document-status and Documents-page
suites passed, including adoption, manual overrides, restoration, validation
reset and source preservation through document selection. TypeScript, ESLint,
production build and Storybook build passed. Browser checks at 1440, 1024, 390 and 320 px
found no horizontal overflow and no axe WCAG A/AA violations in the inspected
main content. Native PDF contents were excluded. The real-backend browser demo
selectors were updated but that demo was not run; browser inspection used
synthetic API responses.

- Document details show the review workspace and recovery actions before
  supplementary information. Review reasons are visible beside the document
  guidance; technical results and AI details are collapsed by default.
- Processing history starts expanded during active processing or AI execution.
  The review note follows the editable fields, and the operator token has an
  explanation associated with its input. Storybook includes both an extracted
  invoice and a missing-extraction review.
