# v0.5.0 - Local Operational Observability

## Scope

`v0.5.0` makes the asynchronous document-processing workflow observable in a
local environment without changing its business contract. It adds bounded,
queryable operational signals for request behavior, pipeline backlog and current
run state, together with a reproducible Prometheus and Grafana setup.

## Included

- a Prometheus `GET /metrics` endpoint outside the versioned `/api/v1`
  business API and OpenAPI contract;
- low-cardinality HTTP request counts and durations grouped only by method,
  matched route template and status class;
- a PostgreSQL-backed snapshot of processing-run counts by bounded status and
  the age of the oldest queued run;
- bounded `X-Correlation-ID` request handling, preserving safe caller values or
  generating a UUID when absent or unsafe;
- one allowlisted JSON application log event for each completed or failed HTTP
  request, plus structured dispatcher outcome events;
- an optional Compose `observability` profile with pinned Prometheus and
  Grafana images, health checks and persistent local volumes;
- a version-controlled Prometheus datasource and read-only **Document Platform
  Operations** Grafana dashboard for scrape health, queue age, run states,
  request rate and p95 latency;
- an operational verification runbook covering correlation, logs, scraping,
  provisioning and release quality gates.

## Verification

Follow the [v0.5 verification runbook](../runbooks/v0.5-verification.md) from
a clean checkout after the local PostgreSQL prerequisites are available.

Local infrastructure verification completed on 2026-09-20:

- the Prometheus configuration passed `promtool check config`;
- Prometheus scraped the API at `host.docker.internal:8000` with
  `up{job="document-platform-api"} = 1`;
- an API request emitted an allowlisted JSON event containing its generated
  correlation ID, route, status and duration;
- Grafana `13.2.2` started healthy, its provisioned Prometheus datasource
  returned `OK`, and the `document-platform-operations` dashboard was present
  with `provisioned: true`;
- dashboard provisioning completed without startup errors or automatic plugin
  downloads.

The final release gate is the complete backend and frontend quality suite and
the equivalent green CI run on the commit selected for the `v0.5.0` tag.

## Deliberately Excluded

- production monitoring deployment, alert delivery and on-call routing;
- production access policy, secret management and multi-user Grafana access;
- W3C Trace Context, Temporal correlation propagation and distributed tracing;
- historical outcome-event analytics or a general audit-event store;
- controlled reprocessing and its operator workflow, reserved for `v0.6.0`;
- retention/deletion workflows, malware scanning and notification delivery;
- S3-compatible storage and external-provider model execution.

The bundled monitoring profile is a local development fixture. Its credentials
and seven-day Prometheus retention are intentionally not presented as a
production configuration.

## Compatibility

The `/api/v1` HTTP namespace and generated OpenAPI contract remain unchanged.
`/metrics` is intentionally operational infrastructure outside OpenAPI.
Existing consumers therefore require no changes. The additional
`X-Correlation-ID` response header is optional metadata and does not alter any
response body.
