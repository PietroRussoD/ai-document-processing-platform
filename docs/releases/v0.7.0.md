# v0.7.0 - Failure Operations

## Scope

`v0.7.0` makes terminal document-processing failures visible and actionable.
When Temporal exhausts an activity's retry policy, the workflow records bounded
failure evidence in PostgreSQL and reconciles the document and processing run
to a terminal failed state.

## Included

- safe failure stage and code on the persisted processing run and current-run
  status response, without exposing exception text, stack traces or document
  content;
- deterministic, local-only extraction fault injection for exercising retry
  exhaustion;
- paginated, metadata-only `ACTIVE`, `REVIEW` and `FAILED` document queues and
  operator-console navigation to durable document detail URLs;
- a database readiness endpoint and low-cardinality persisted failure metrics;
- a Grafana panel for failed-run counts by bounded stage and code;
- updated OpenAPI-generated frontend types, ADR 0008 and the
  [v0.7 verification runbook](../runbooks/v0.7-verification.md).

## Compatibility

The `/api/v1` namespace remains unchanged. Queue and status responses add
bounded metadata; they do not return extracted text, blob paths or raw failure
details. Existing upload, review and controlled-reprocessing flows remain
available.
